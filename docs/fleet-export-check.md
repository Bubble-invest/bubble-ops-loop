# Fleet daily management KPI sidecars

The independent fleet timer writes `outputs/<day>/4/management-kpis.yaml` for departments whose `dept.yaml` declares `status: live` (case-insensitive, at root or under `department`) and `layers.subscribed` includes integer `4`. The department still writes its mandatory `management-export.yaml` and candid `summary.md`, including what went wrong. The checker never edits the model's export: comments, wrapping and every byte remain intact.

The sidecar contains `dept`, `date`, real UTC `generated_at`, `export_present`, `export_shape`, one-line `export_shape_note`, flat numeric `top_kpis`, `missions`, `dept_tokens_today`, structured `attention`, `links`, `sources_missing`, `sources_not_configured`, and `dispatch_days_absent_list`. Shapes are `schema`, `wrapped:<key>`, `nonconforming`, `unparseable`, or `absent`; notes identify missing/extra root key names without copying values. Present exports that are not schema-shaped get low `kpi-export-nonconforming` attention. An absent/blank day report gets low `kpi-day-report-missing` attention; only a nonblank report gets `links.day_report`. Each successful non-dry run atomically replaces the sidecar at mode 0644 as the department owner, refreshing late activity and the writing timestamp.

The consumer, the CEO department's L1 reader, must read the sidecar. That reader change belongs in the CEO department's repository and is **not part of this PR**. A sidecar can exist with `export_present: false`; it does not satisfy the department's mandatory model-export obligation.

Security model (six lines):

1. Root lists `AGENTS_ROOT` names and lstats each entry; it never opens, parses or follows file metadata inside a department.
2. Root rejects symlinks, non-directories, UID 0 and owners other than `agent-<directory-slug>`, and requires `pw_uid == st_uid`; explicit trusted owner overrides change only the expected name and cannot bypass UID 0 refusal.
3. Root launches exactly one `runuser -u <owner> -- <python> -I <framework-child>` per accepted directory, with framework cwd and a 120-second hard timeout.
4. The owner child refuses UID 0, reads eligibility, sources and model shape using safe YAML, reports symlink/non-regular output components or files as errors, and opens regular files with `O_NOFOLLOW` through pinned directories.
5. The child caps model exports and manifests at 1 MiB; export parsing failures become `unparseable`; sidecars use same-directory `mkstemp` plus `os.replace`.
6. Root caps child stdout at 4096 bytes, accepts exactly one JSON `status` field and matching exit code, kills timed-out process groups, and stores alarm receipts only in its own state directory.

Checks run at 21:50 and 23:30 Europe/Paris for today, then 08:10 for yesterday. `Persistent=true` catches a missed timer activation. Before noon the default reporting day is yesterday; afterwards it is today. Only eligible departments with `export_missing` alarm after 23:30 on the report date (or for a past date). Skips and child errors do not alarm. Incidents use stable `fleet-export-missing-<slug>-<day>` IDs, positive `budget=5` and the existing system convergence intent. All alarm text comes from the root-derived validated slug and canonical day, never model content. Only successful emitter acceptance creates a receipt; failed emissions retry on the next run, then stop after success. A root state lock serializes runs. Emitter calls have a 60-second timeout; the service has `TimeoutStartSec=20min` and group cleanup.

Exit codes: 2 means nothing processed (no child returned `written` or `export_missing`), with one explicit error log line, including dry runs. When at least one department is processed, 0 means success and 1 means a child or emitter failed; configuration/enumeration failures also exit 1. Only `not-live`, `no-l4` and `invalid-manifest` use `skipped:`; filesystem refusals use `error:` and the child exits 1.

## Mac-hosted departments

Content (jade-m1), accountant (its Mac), and rnd (the operator's Mac) run the sidecar writer locally as the department's own user. The VPS never writes into their read-only git mirrors. Install from the framework checkout on each Mac, substituting the actual Claude transcript project directory:

```bash
# On jade-m1:
scripts/install-mac-export-kpis.sh --slug content \
  --dept-dir "$HOME/claude-workspaces/bubble-ops-content" \
  --transcripts-dir "$HOME/.claude/projects/<escaped-content-path>"
# On the accountant Mac:
scripts/install-mac-export-kpis.sh --slug accountant \
  --dept-dir "$HOME/claude-workspaces/bubble-ops-accountant" \
  --transcripts-dir "$HOME/.claude/projects/<escaped-accountant-path>"
# On the operator's Mac:
scripts/install-mac-export-kpis.sh --slug rnd \
  --dept-dir "$HOME/claude-workspaces/Rick_RnD" \
  --transcripts-dir "$HOME/.claude/projects/<escaped-Rick_RnD-path>"
```

Add `--framework-root /path/to/bubble-ops-loop` to reference a stable framework checkout, or `--dry-run` to print the validated plist and launchctl commands without changing anything. The installer writes `~/Library/LaunchAgents/com.bubble.export-kpis-<slug>.plist`, validates with `plutil -lint` when available, and uses `launchctl print`, conditional `bootout`, and `bootstrap` in `gui/<uid>`. A failed replacement restores and reloads the previous definition. It requires Python 3.9+ with Europe/Paris timezone data and PyYAML importable under `python3 -I` (a user-site-only installation is insufficient).

The LaunchAgent fires at 21:50, 23:30 and 08:10 **Mac local time**, without KeepAlive. Launchd uses one argument list for all calendar entries, so its launcher selects `--also-yesterday` before noon, including morning wake catch-up; evening runs write today only. Report dates use Europe/Paris. Both streams append to `~/Library/Logs/export-kpis-<slug>.log`. Manual backfill: `scripts/mac-export-kpis.sh --dept-dir DIR --transcripts-dir DIR --day YYYY-MM-DD --also-yesterday`; the extra day is the day preceding the selected report date. `--dry-run` reads eligibility/export presence but writes no sidecar. The wrapper prints one child JSON status per day and exits nonzero for a child error. Normal statuses remain `written`, `export_missing`, `skipped:*`, and `error:*`.

The VPS adds an **alarm-only** mirror pass only from 06:00 (inclusive) to 12:00 (exclusive) Europe/Paris when the report day is yesterday. A delayed persistent activation at 00:05 does not inspect or alarm on mirrors. It considers `AGENTS_ROOT/bubble-ops-<slug>` symlinks whose resolved targets are directories immediately under `FLEET_EXPORT_MIRROR_ROOT` (default `/home/claude/agents`). A real `AGENTS_ROOT/<slug>` directory takes precedence. Symlink loops and targets with UID 0 or owners other than `FLEET_EXPORT_MIRROR_OWNER` (default `claude`, independent of real-department owner overrides) are refused. Root reads only symlink path strings and directory metadata; it never opens or parses mirror files. It launches the existing isolated child as the mirror owner with `--check-only`. This mode retains manifest/live/L4 eligibility and output symlink/regular-file/size rules, never creates directories or files, and checks mirror freshness before inspecting outputs. As the mirror owner, the child directly reads `.git/HEAD`, the named local `refs/heads/<branch>` commit, and `refs/remotes/origin/<same branch>`; absent loose refs fall back to `.git/packed-refs`. It reads only the mtime of `.git/FETCH_HEAD` through an opened regular-file descriptor. All directories are pinned and opened with `O_NOFOLLOW`, and file reads use the existing no-follow helpers with a 1 MiB cap. The child never executes git, loads git config, invokes a subprocess, or accesses the network.

The mirror is `mirror_stale` if local and remote-tracking commits differ, either commit is missing, HEAD/ref evidence is unreadable or malformed (including detached HEAD), or `FETCH_HEAD` is absent, unreadable, or older than 6 hours. `--mirror-max-age-hours HOURS` on `scripts/fleet-export-check.sh` or the check-only child changes this threshold. A current mirror proceeds to `export_present` / `export_missing`; a stale mirror leaves export status unknown. All three are successful child statuses (exit 0) accepted only in the mirror pass and count as processed departments; real-department statuses, exit semantics and alarms remain unchanged.

Mirror alarms have two separate card types:

- A **current mirror with a missing export** emits stable task ID `fleet-export-missing-<slug>` and title `Missing daily management export: <slug> since <first missing day>`. Its receipt is `<state>/fleet-export-missing-<slug>.mirror.json`, with `first_missing_day` and `last_alarm`. An eligible `export_present` clears this receipt.
- A **stale mirror** emits stable task ID `fleet-mirror-stale-<slug>` and title `VPS mirror of <slug> is not updating since <first stale day>`. Its separate receipt is `<state>/fleet-mirror-stale-<slug>.mirror.json`, with `first_stale_day` and `last_alarm`. The card directs investigation to VPS sync and file ownership. No missing-export card is raised while the mirror is stale; an existing missing-export receipt is preserved because export status is unknown. Either current-mirror status clears the stale receipt, even if the export remains missing.

Root's state lock covers both receipts. The first day is the report day when that outage was first observed. `last_alarm` is initially null and becomes the report day of successful emission. Failed emits retry while preserving the first day; success suppresses further cards across days until recovery clears that receipt. Later outages can alarm again. An unreadable, corrupt or oversized receipt (over 4096 bytes) logs one warning and is treated as absent, then replaced on the next write. Skips/errors leave both receipts intact. Alarm text contains only validated root-derived slugs and canonical days, never mirror content. Dry run writes or clears no receipt and emits nothing. Evening checks and manual backfills outside the 06:00–12:00/yesterday condition do not inspect mirrors.

A Mac that is off writes no sidecar. Content/accountant sidecars reach the VPS only after normal department commits push the tracked outputs and the mirror refreshes; rnd publishes through its own outputs script. The LaunchAgent does not commit, push or publish anything. A stale VPS mirror triggers its sync card and suppresses missing-export inference. A current mirror can still lack an unpublished local export, so the missing-export card asks about the Mac runtime and outputs publication. Actual launchctl behavior, mirror owners/layout, refresh cadence and department publication require live verification.

The 28-day run-count window includes the report day. VPS `outputs/<day>/dispatch.json` ledgers retain their existing writer and shape: mission keys, `dispatched_at`, `completed_at`, and listed `artifacts` (including trigger entries). Dispatch/transcript days use Europe/Paris. `runs_recorded` counts all observed runs; `runs_dispatched` and `days_dispatched` require a known start, `runs_completed` requires a completion, and `runs_unattributed` counts runs without a usable start/completion window.

For the Mac `loop.due_dispatch` schema, `scripts/due_missions.py complete` appends each verified success to a sibling `outputs/<day>/due-dispatch.json` JSON array. Each record contains `mission_id`, `period`, and UTC `completed_at`. A matching pending lease supplies `leased_at` and `dispatched_at`, captured before the success watermark clears it. The ledger day is the completion's Europe/Paris date; a lease may have started on an earlier day. A success without a known lease (including continuous missions) has no invented start: it counts as completed and unattributed. Acknowledgements with the same mission, period and completion timestamp are idempotent; distinct acknowledgements are retained instead of overwriting earlier runs. The reader consumes both ledgers. Mac mission entries include `history_days_present` and `history_days_absent`, even for missions with no observed runs; sparse history does not imply zero runs on missing days.

The Mac ledger uses a sibling `.due-dispatch.lock`, pinned directory descriptors, owner checks, `O_NOFOLLOW` regular-file checks, a mode-0600 temporary file, fsync and atomic replacement. It runs as the existing completion caller, with no owner transition. Ledger/lease-evidence errors log a `due-mission KPI ledger warning` to stderr and never change the verified completion's stdout, exit status or scheduling watermark. Planning, wake-prompt generation and delivery/lease outcomes remain unchanged; this success ledger does not record failed, blocked or merely delivered work, and cannot reconstruct earlier watermark-only history.

Transcript discovery includes subagent JSONLs; duplicate assistant IDs retain the fullest usage. Mission `*_tokens_approx` and `cost_usd_estimate_approx` cover **the report day**, identified by `tokens_date`, while run counters cover 28 days. Attribution unions inclusive start/completion windows per mission. Each report-day call is assigned once: when several missions' windows contain it, each integer token class is divided evenly, with deterministic remainders. A mission with an intersecting report-day window carries `attribution: shared_window` and sorted `shared_with: [mission_ids]`, including when no call falls in the overlap. Non-overlapping calls keep their full attribution. The sum of mission token counts cannot exceed `dept_tokens_today` (unmatched calls remain department-only); costs are estimated from each mission's allocated tokens. Metadata stays in `missions`; flat `top_kpis` contains only numeric fields.

Dollar estimates reuse the framework console's importable default pricing constant and all four token classes; unpriced models omit dollar estimates. Missing or malformed sources remain visible without inventing zero totals; an incomplete transcript scan suppresses token totals. Optional offline inputs are `monitoring/runs.json`, `monitoring/board-issues.json` and ordered `config/mission_kpi_map.yaml` title regex/job mappings. No department code or library copy is imported.

Flat `dispatch_days_present` counts days with a readable dispatch JSON object or Mac success array (including empty ledgers), once per day even if both exist; `dispatch_days_absent` counts the remaining window days. The body lists those ISO days chronologically in `dispatch_days_absent_list`. A day without a ledger is normal and produces no source error or attention item. If no ledger is readable in the window, `sources_missing` includes `dispatch`; existing unreadable or invalid dispatch evidence also uses that single identifier, never per-day entries. Absent optional sources are listed by their source identifiers (`board`, `runs`, `mission_map`) in `sources_not_configured` and produce no attention. Required unreadable sources (`transcripts`, `dispatch`, `dept.yaml`) and existing unreadable/invalid optional sources remain in `sources_missing` and produce low `kpi-sources-missing` attention.

All `*_mtok` figures are rounded to one decimal, token counts remain integers, and dollar values are rounded to two decimals. Heavy token use attention includes millions to one decimal and the model-call count, for example: "Department used 34.8 million tokens across 318 model calls on 2026-10-02". Thresholds still use the unrounded integer token total.

Deploy after merge:

1. Fast-forward the clean framework checkout at `/opt/bubble-ops-loop` to the merged revision. Ensure system Python has PyYAML visible with `python3 -I -c 'import yaml'`, Europe/Paris zone data, and Linux `/proc/self/fd`.
2. As root run `/opt/bubble-ops-loop/scripts/install-fleet-export-check.sh`, then `scripts/fleet-export-check.sh --dry-run` (optionally `--day YYYY-MM-DD`). Dry run launches read-only owner children but writes no sidecars/receipts and invokes no emitter.
3. Verify eligible departments, Unix owners, `systemctl list-timers fleet-export-check.timer`, and `journalctl -u fleet-export-check.service`. Ensure the existing emitter authenticates as root. Inspect sidecars as their owners and verify model-export bytes remain unchanged.

Rollback: `systemctl disable --now fleet-export-check.timer`. Nothing else needs undoing because model exports are never touched; existing sidecars and alarm receipts can remain.

Trusted configuration: `FLEET_EXPORT_MIRROR_ROOT`, `FLEET_EXPORT_MIRROR_OWNER`, `AGENTS_ROOT`, `TRANSCRIPTS_ROOT` (one tree per directory slug), `FLEET_EXPORT_STATE_DIR`, `PYTHON_BIN`, `RUNUSER_BIN`, `EMIT_BIN`, `TOKEN_THRESHOLD`, `FLEET_EXPORT_NOW` (timezone-aware ISO timestamp), and `FLEET_EXPORT_OWNER_OVERRIDES="slug=user,slug2=user2"` for legacy owners/tests. Executable overrides are individual paths, not shell commands. There is no direct nonroot execution fallback; the coordinator always invokes runuser. Production framework code, executable overrides and the root state directory must be controlled by the operator.

Limits: VPS counts cover surviving dispatch records; overwritten cycles and crashes before COMMIT cannot be reconstructed. Mac counts cover successful acknowledgements recorded after this change; earlier history, failed deliveries and runs lacking an acknowledgement are unobservable. Start-less successes have no token attribution. Token windows can include unrelated calls; overlapping calls are shared estimates and costs remain estimates. This is a bounded owner-level read/write process, not a full OS sandbox. Concurrent department edits can change the evidence snapshot; subsequent runs refresh it. A service-wide timeout can stop a large fleet before every department runs; `--day` supports manual backfill. Root UID isolation, Linux directory-descriptor publication, timer catch-up and actual board delivery require deployment verification; offline tests cannot prove those production effects.

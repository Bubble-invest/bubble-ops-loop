# Fleet daily management exports

The root fleet timer checks each real directory with a `dept.yaml` under `/srv/agents`, independently of agent sessions. It enriches an existing `outputs/<day>/4/management-export.yaml` as the directory's Unix owner, using the framework libraries in `/opt/bubble-ops-loop`. It never creates an export in place of the department. New L4 prompts require that export and a candid `outputs/<day>/4/summary.md` day report every day.

Checks run at 21:50 and 23:30 Europe/Paris for today, then at 08:10 for yesterday. Missing exports produce a journal line and a high-priority board incident through `tools/kanban/emit_kanban_item.sh`. The task and title both contain the department and reporting date. A successful emitter receipt under `/var/lib/bubble-fleet-export-check` suppresses repeat calls even if the card is later closed; failed emissions retry. A lock serializes checks. The emitter requires a positive remediation budget: these incidents use `budget=5` and the system convergence intent. Board delivery uses the emitter's existing authentication and fallback queue; the checker reads no env files.

The 28-day KPI window includes the report date. Dispatch counts use `dispatch.json` mission keys and `dispatched_at` / `completed_at`, not materialization stamps or due watermarks. Artifact counts count listed evidence entries, including `trigger:` entries when present. Transcript timestamps and dispatch calendar dates use Europe/Paris, including subagent JSONLs. Duplicate assistant message ids retain the fullest usage record. Anonymous messages remain separate. Mission tokens are approximate sums within inclusive dispatch/completion windows; a message is counted once per mission even across overlapping windows. Dispatches without both timestamps are counted as unattributed.

Missing, unreadable, or malformed sources appear in `sources_missing` and a low-priority attention item. Dispatch counts cover observed surviving records; missions without observations have no zero counts when any ledger in the window is missing. An incomplete transcript scan suppresses all token totals. Optional offline inputs default to `monitoring/runs.json` and `monitoring/board-issues.json`, with `config/mission_kpi_map.yaml` containing ordered `titles` regex and `jobs` lists per mission. Explicit `--runs-json` and `--board-json` flags on the KPI CLI override those paths. Card matching, drop rates, run failures, and last-run ties follow the reference implementation.

Dollar estimates reuse only the console cost tracker's importable default pricing table, include all four token classes, and are estimates rather than billing figures. Unknown models omit the dollar figure for their aggregate; token counters remain available. No console report, pricing override file, or cache is read or written. KPI libraries are not vendored: only the independent fleet checker needs them.

Enrichment preserves existing KPI keys, model attention, string-form notes, and schema-supported optional root fields. It adds absent numeric KPIs, deduplicates attention by id, stamps `export_enriched: 1`, and sets `links.day_report` to the canonical nonempty summary when available. That navigation key is the explicit replacement exception. A conflicting existing enrichment stamp, duplicate YAML key, invalid schema, or mismatched date fails without changing the export. Atomic replacement preserves file permissions; YAML formatting/comments can change on the first enrichment. A repeat enrichment is byte-for-byte unchanged.

Deploy after merge:

1. Fast-forward the clean framework checkout at `/opt/bubble-ops-loop` to the merged revision.
2. As root, run `/opt/bubble-ops-loop/scripts/install-fleet-export-check.sh` (system Python needs PyYAML and Europe/Paris zone data).
3. Run `/opt/bubble-ops-loop/scripts/fleet-export-check.sh --dry-run` and optionally `--day YYYY-MM-DD`; verify each department and its owner in the output.
4. Verify `systemctl list-timers fleet-export-check.timer` and `journalctl -u fleet-export-check.service` after the scheduled run. Ensure the existing board emitter can authenticate under root.

Rollback: `systemctl disable --now fleet-export-check.timer`. Existing exports and alarm receipts remain available.

Offline testing overrides: `AGENTS_ROOT`, `TRANSCRIPTS_ROOT` (one transcript tree per directory slug), `FLEET_EXPORT_STATE_DIR`, `PYTHON_BIN`, `RUNUSER_BIN`, `EMIT_BIN`, `TOKEN_THRESHOLD`, and `FLEET_EXPORT_NOW` (ISO timestamp with timezone). Executable overrides are single paths, not shell command strings. Nonroot runs execute writes directly. `--dry-run` never writes files or invokes the emitter or owner commands.

Known limits: ledgers retain only the latest same-day dispatch for a mission and accumulated artifacts; overwritten cycles and workers that crashed before COMMIT cannot be reconstructed or diagnosed from that evidence. Attribution can overlap between missions and includes unrelated calls in a run's time window. Enrichment runs once per export, so late activity is not refreshed after the stamp. Invalid existing exports log errors but are not classified as missing. Timers do not catch up missed activations; backfill with `--day`. The default day selector checks yesterday before noon and today afterwards. Board delivery and actual UID isolation require VPS verification. Older architecture/schema prose names an export outside `4/`; this checker follows live `dept_liveness` and the L4 template's `4/` path.

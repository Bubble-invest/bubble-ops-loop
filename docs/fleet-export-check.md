# Fleet daily management KPI sidecars

The independent fleet timer writes `outputs/<day>/4/management-kpis.yaml` for departments whose `dept.yaml` declares `status: live` (case-insensitive, at root or under `department`) and `layers.subscribed` includes integer `4`. The department still writes its mandatory `management-export.yaml` and candid `summary.md`, including what went wrong. The checker never edits the model's export: comments, wrapping and every byte remain intact.

The sidecar contains `dept`, `date`, real UTC `generated_at`, `export_present`, `export_shape`, one-line `export_shape_note`, flat numeric `top_kpis`, `missions`, `dept_tokens_today`, structured `attention`, `links`, and `sources_missing`. Shapes are `schema`, `wrapped:<key>`, `nonconforming`, `unparseable`, or `absent`; notes identify missing/extra root key names without copying values. Present exports that are not schema-shaped get low `kpi-export-nonconforming` attention. An absent/blank day report gets low `kpi-day-report-missing` attention; only a nonblank report gets `links.day_report`. Each successful non-dry run atomically replaces the sidecar at mode 0644 as the department owner, refreshing late activity and the writing timestamp.

The consumer, the CEO department's L1 reader, must read the sidecar. That reader change belongs in the CEO department's repository and is **not part of this PR**. A sidecar can exist with `export_present: false`; it does not satisfy the department's mandatory model-export obligation.

Security model (six lines):

1. Root lists `AGENTS_ROOT` names and lstats each entry; it never opens, parses or follows file metadata inside a department.
2. Root rejects symlinks, non-directories, UIDs below 1000 and owners other than `agent-<directory-slug>`; explicit trusted owner overrides retain the UID rule.
3. Root launches exactly one `runuser -u <owner> -- <python> -I <framework-child>` per accepted directory, with framework cwd and a 120-second hard timeout.
4. The owner child reads eligibility, sources and model shape using safe YAML, refuses symlink output components/model files, and opens regular files with `O_NOFOLLOW` through pinned directories.
5. The child caps model exports and manifests at 1 MiB; export parsing failures become `unparseable`; sidecars use same-directory `mkstemp` plus `os.replace`.
6. Root caps child stdout at 4096 bytes, accepts exactly one JSON `status` field and matching exit code, kills timed-out process groups, and stores alarm receipts only in its own state directory.

Checks run at 21:50 and 23:30 Europe/Paris for today, then 08:10 for yesterday. `Persistent=true` catches a missed timer activation. Before noon the default reporting day is yesterday; afterwards it is today. Only eligible departments with `export_missing` alarm after 23:30 on the report date (or for a past date). Skips and child errors do not alarm. Incidents use stable `fleet-export-missing-<slug>-<day>` IDs, positive `budget=5` and the existing system convergence intent. All alarm text comes from the root-derived validated slug and canonical day, never model content. Only successful emitter acceptance creates a receipt; failed emissions retry on the next run, then stop after success. A root state lock serializes runs. Emitter calls have a 60-second timeout; the service has `TimeoutStartSec=20min` and group cleanup.

The 28-day KPI window includes the report day. Ledgers use mission keys, `dispatched_at`, `completed_at`, and listed `artifacts` (including trigger entries). Dispatch/transcript days use Europe/Paris. Transcript discovery includes subagent JSONLs; duplicate assistant IDs retain the fullest usage. Approximate mission attribution unions inclusive dispatch/completion windows and uses `_approx` names. Dollar estimates reuse the framework console's importable default pricing constant and all four token classes; unpriced models omit dollar estimates. Missing or malformed sources remain visible without inventing zero totals; an incomplete transcript scan suppresses token totals. Optional offline inputs are `monitoring/runs.json`, `monitoring/board-issues.json` and ordered `config/mission_kpi_map.yaml` title regex/job mappings. No department code or library copy is imported.

Deploy after merge:

1. Fast-forward the clean framework checkout at `/opt/bubble-ops-loop` to the merged revision. Ensure system Python has PyYAML visible with `python3 -I -c 'import yaml'`, Europe/Paris zone data, and Linux `/proc/self/fd`.
2. As root run `/opt/bubble-ops-loop/scripts/install-fleet-export-check.sh`, then `scripts/fleet-export-check.sh --dry-run` (optionally `--day YYYY-MM-DD`). Dry run launches read-only owner children but writes no sidecars/receipts and invokes no emitter.
3. Verify eligible departments, Unix owners, `systemctl list-timers fleet-export-check.timer`, and `journalctl -u fleet-export-check.service`. Ensure the existing emitter authenticates as root. Inspect sidecars as their owners and verify model-export bytes remain unchanged.

Rollback: `systemctl disable --now fleet-export-check.timer`. Nothing else needs undoing because model exports are never touched; existing sidecars and alarm receipts can remain.

Trusted configuration: `AGENTS_ROOT`, `TRANSCRIPTS_ROOT` (one tree per directory slug), `FLEET_EXPORT_STATE_DIR`, `PYTHON_BIN`, `RUNUSER_BIN`, `EMIT_BIN`, `TOKEN_THRESHOLD`, `FLEET_EXPORT_NOW` (timezone-aware ISO timestamp), and `FLEET_EXPORT_OWNER_OVERRIDES="slug=user,slug2=user2"` for legacy owners/tests. Executable overrides are individual paths, not shell commands. There is no direct nonroot execution fallback; the coordinator always invokes runuser. Production framework code, executable overrides and the root state directory must be controlled by the operator.

Limits: only surviving dispatch records are observable; overwritten cycles and crashes before COMMIT cannot be reconstructed. Token windows may overlap between missions and include unrelated calls; costs are estimates. This is a bounded owner-level read/write process, not a full OS sandbox. Concurrent department edits can change the evidence snapshot; subsequent runs refresh it. A service-wide timeout can stop a large fleet before every department runs; `--day` supports manual backfill. Root UID isolation, Linux directory-descriptor publication, timer catch-up and actual board delivery require deployment verification; offline tests cannot prove those production effects.

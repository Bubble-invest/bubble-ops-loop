# Signed A2A relay (#1600)

Deploy only after the infra PR and Joris's structural mandate PR are reviewed and merged. This change does not deploy keys or restart agents.

1. On Rick's Mac, generate a dedicated sender key:
   `ssh-keygen -t ed25519 -C a2a-rick -f ~/.ssh/a2a_ed25519`.
   The current unattended sender requires an empty passphrase. Keep the private key on the sender host only, mode 600; never copy it to receivers. Any process under that host's OS user can potentially read it. Other principals get separate keys.
2. On M1 (Miranda receiver), configure `$TELEGRAM_STATE_DIR/a2a_allowed_signers` with a line `rick namespaces="bubble-a2a" ssh-ed25519 <Rick-public-key-base64>`. Use the contents of the PUBLIC `.pub` file. Add other approved principals on separate lines. Missing/invalid allowlists fail unverified.
3. Install the merged framework, run `scripts/install-channel-patches.sh --strict` for the intended plugin dir (see `--help`), then restart Miranda through her normal runner. The installer upgrades marked and recognized pre-marker inject blocks, validates the combined plugin with Bun and restores on failure. `apply-inject-patch.sh` delegates to it. Verify one harmless synthetic relay and its actual metadata before enabling approval use.
4. Send with `scripts/a2a-send.sh --to <M1-SSH-alias> --state-dir <exact-absolute-state-dir> --from rick < message.txt`. The default key is `~/.ssh/a2a_ed25519`; override with `--key`. Destination must exactly match the receiver's configured state directory, including trailing-slash spelling. Python 3, OpenSSH supporting `-Y sign/verify`, and the plugin's Bun runtime are required. Message data travels only through stdin/file bytes, never command arguments.
5. Rotate by generating a fresh key on the sender, adding its public key under the same principal on each receiver, switching sender `--key`, then removing the old allowed-signer entry. Revoke by removing all entries for the compromised key on every receiver; the allowlist is read on each verification. Do not delete the replay cache during rotation.

Wire format: `BUBBLE-A2A-SIGNED <base64 UTF-8 JSON> <base64 SSH signature>`. The sender uses sorted compact JSON without a trailing newline, v=1, from, to_state_dir, UTC ISO ts, random 128-bit nonce and body. Verification authenticates the exact envelope bytes with namespace `bubble-a2a`. It checks the principal, destination, ±10-minute clock window and persisted replay cache before setting `a2a_sender` and `a2a_verified="true"` (channel metadata uses strings). Unsigned lines preserve legacy delivery with `a2a_verified="false"`; failed signed lines visibly deliver untrusted text and never a trusted sender.

Replay entries expire at envelope timestamp +10 minutes (including future-dated envelopes). Cache capacity is 10,000 live entries; capacity, corrupt cache, lock contention, write failure or verification timeout fails unverified. A crashed verifier may leave `a2a_replay.lock`: stop consumers and remove only that lock after verifying no writer remains. Preserve `a2a_replay.json`. Cache commit precedes notification: failed notifications cannot be retried as verified with the same nonce. This is not an exactly-once execution/delivery queue; the existing file drain is still best effort.

## Threat model

An attacker who can append to inject cannot forge an allowed sender's signature, change the body/destination/timestamp, or replay an accepted envelope while the verifier and its persistent state remain trusted. Wrong signatures, keys, principals, stale/future timestamps, destination mismatches and replay fail unverified. Unsigned text, operator chat IDs and visible labels are never approval evidence.

This does NOT protect against a compromised Rick host, another process reading his same-user key, or a misled/prompt-injected Rick signing an inappropriate approval (risk accepted in the card). It proves Rick signed bytes, not that Joris spoke them. It also does NOT withstand a compromised receiver able to modify the verifier, allowed_signers, replay cache or channel metadata. All agents sharing an OS account means file permissions are hygiene, not isolation: arbitrary code execution as that user can replace trust anchors. Strong protection against that requires a separately privileged verifier/trust store and transport, outside this patch's scope. Do not describe this as unforgeable against full receiver-host compromise. No confidentiality beyond SSH, human-approval bypass, or public-publishing permission is added.

The card originally suggested SSH forced commands. Detached signatures are used per BRIEF.md because a shared-user writable inject file cannot by itself authenticate a claimed sender. The receiver runtime and trust store still need to be trusted.
